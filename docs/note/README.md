# note 入稿メモ（人狼ゲームの紹介記事）

このフォルダの中身。

```
docs/note/
├── werewolf-note-article.md   記事本文。そのまま note に貼れる形
├── images/                    実際にアプリを操作して撮った画面 25 点
└── README.md                  このファイル
```

## 貼る前に直すところ

**連載番号が `#◯` のままです。** 1行目のタイトルにある `#◯` を、正しい号数に
書き換えてください。ここだけは推測で埋めていません。番号を間違えると連載が壊れるためです。

タイトルの候補は次のとおりです。しっくりこなければ差し替えてください。

- 「先生が司会をしなくていい」ふりがなつきで1台からできる人狼ゲームアプリ「人狼ゲーム」
- 「話し合いが続かない」を変える。タブレット1台をまわすだけの人狼ゲームアプリ「人狼ゲーム」
- 準備はタブレット1台だけ。全員に話す理由が生まれる人狼ゲームアプリ「人狼ゲーム」

## note へ貼る手順

1. note で新しい記事を作り、`werewolf-note-article.md` の1行目（`# ` を除いた部分）を
   タイトル欄に貼ります。
2. 2行目以降を本文欄に貼ります。`## 🏫 はじめに` のような見出し行は、note のエディタで
   見出し（大見出し）に変換してください。note は見出しから目次を自動生成します。
3. 画像は自動では入りません。`images/` の中の画像を、本文の `![...](images/...)` が
   書かれている位置に手でアップロードします。ファイル名の数字の順番と、本文に出てくる
   順番はそろえてあります。
4. 画像を置いたら、`![...](images/...)` の行と、その直後のキャプション行を本文から消し、
   キャプション行の文章を note の画像キャプション欄に入れてください。
5. ハッシュタグは `#GIGAスクール` `#ICT教育` `#人狼ゲーム` `#小学校` `#学級経営`
   `#PWA` あたりが合いそうです。
6. 見出し画像には `images/01-home.png` か `images/24-result.png` が向いています。

本文には太字・斜体・表・記号（矢印やスラッシュ）を一切使っていません。note のエディタに
そのまま貼れることを優先しています。

## 撮り直すときの手順

撮影用のシナリオは納品時に消してあります。撮り直すときは、次の手順で作り直してください。

1. リポジトリのルートで `npm i --no-save playwright` と `npm run build` を実行します。
2. 本番と同じサブパスで配ります。ルート直下で配ると Service Worker と manifest の
   挙動が本番と変わるので、第3引数の `/Werewolf/` を省かないでください。

   ```bash
   node <skill>/scripts/serve.mjs dist 4180 /Werewolf/
   ```

3. `.tmp-shots/shots.mjs` のようなシナリオを書き、次のように撮ります。

   ```bash
   node <skill>/scripts/capture.mjs .tmp-shots/shots.mjs \
     --base http://127.0.0.1:4180/Werewolf/ --out shots
   ```

4. 撮り終わったら `.tmp-shots/` を消し、`git status` に残っていないか確かめます。

撮るときに引っかかったところを残しておきます。

- ボタンの文字にはふりがな（`<ruby>`）が入っているので、`textContent` は
  「役職やくしょく」のようになります。`<rt>` と `<rp>` を落としてから比べないと当たりません。
  スキルの `capture.mjs` の `click()` はこれをやってくれます。
- 役職のカスタマイズの `+` と `-` はどちらも文字が `+` `-` なので、文字では探せません。
  `aria-label`（`村人を増やす` など）で押します。
- 役職の合計が遊ぶ人数に達すると `+` が押せなくなります。増やす前に減らす順番で
  操作しないと、途中で詰まります。
- 役職カードとホーム画面は縦に長いので、`resize(800, 1560)` などで
  ビューポートを伸ばしてから撮ると1枚に収まります。
- 役職はゲームごとにシャッフルされます。誰が何なのかは画面から読み取って、
  そのつど分岐する形にしてください。
- 決選投票の画面を撮るには、票をわざと同数に割る必要があります。
  候補になった2人は決選投票では投票できないので、投票の割りふりは分けて考えます。
- 提示モードは横長のビューポート（1440x1150 で撮りました）にしてから押すと、
  電子黒板に映したときの見えかたに近づきます。

## 文体について踏襲したこと

- 太字、斜体、表、`→` や `／` のような記号は使っていません
- 箇条書きは手順のところだけです。それ以外は文章で書いています
- 専門用語は日常の言葉に置きかえています。PWA は「端末に入れる」、
  ローカルストレージは「その端末のなかだけに残ります」、CSP や Service Worker は
  そもそも出していません
- 絵文字は見出しだけです
- 子どものことは「子どもたち」、読み手は「先生」「先生方」で統一しています
- 導入のメリットは「三つのいいことが期待できます。」から始める型にしています
- 効果は言い切らず、「〜だと思います」「〜のではないかと思っています」で止めています
- 結びは「一歩踏み出そうとする先生を、私はいつでも全力で応援しています。」です
